# naoblock builder 手順書（プロト：Nouns × 40×40 平面）

スマホのちーちゃん（実装）へ。MacBook のちーちゃん（検証）が下の「検証チェックリスト」で確かめるので、その前提で作ってください。
なおなおと 2026-10-12 に壁打ちして決めた内容です。決定事項は勝手に変えず、迷ったらなおなおに聞いてください。

## 1. 作るもの

Nouns の番号を入れると、**ナノブロックの基本パーツで組める「40×40 の平面ドット絵」の組立図**を出す Web アプリ。
画面で見られて、印刷すればそのまま PDF になる。

最終的には「キャラを選ぶ（MCP）→ チビ化 → 立体のミニナノ組立図」まで広げるが、**プロトは平面・Nouns だけ**。
平面で全体の流れ（ドット → 色合わせ → パーツ割り → 組立図 → HTML/PDF）を通し、立体はその後。

## 2. 決定事項（変えない）

| 項目 | 決定 |
|---|---|
| 形 | 平面。プレートの上に 1 段だけブロックを並べる |
| 土台 | 20×20 プレートを 2×2 で 4 枚＝ 40×40。枚数は設定値として持つ（プロトは 4 枚固定でよい） |
| 配置 | Nouns の 32×32 を、40×40 の真ん中（上下左右に 4 ポッチの余白）に 1 ドット＝1 ポッチで置く。縮めない |
| 背景 | **ブロックを置かない**（プレートの色のまま）。Nouns の背景色（d5d7e1 / e1d7d5）は使わない |
| パーツ | パラ売りの長方形の基本パーツだけ：1×1・1×2・1×3・1×4・1×6・2×2・2×3・2×4・2×8（回転可）。特殊形（1×1R・1×2A など）は使わない |
| 色 | 単色部品で買える色だけ（下の表）。クリア・クリアブルーは使わない |
| 出力 | HTML で表示、印刷用 CSS で A4 の PDF |
| 置き場所 | このリポジトリ（naonao1971/naoblock-builder）。GitHub Pages で公開。完成後に naoblock.jp からリンク |

## 3. 技術の方針

- ビルドなしの静的サイト。`index.html` ＋ ES Modules（素の JS）。ライブラリは使わない
- **中身の計算（Nouns の取得以外）は純粋な関数**にして、ブラウザでも Node でも `import` できるようにする（検証で Node から呼ぶため）
- URL の `?noun=11` で番号を指定できるようにする（検証と共有のため）

ファイル構成の目安：

```
index.html
src/nouns.js      … seed の取得と 32×32 への復元
src/palette.js    … ブロックの色の表と、いちばん近い色を選ぶ処理
src/tiling.js     … パーツ割り（純粋関数）
src/plan.js       … 部品リスト・購入リスト・組立手順の組み立て（純粋関数）
src/render.js     … 画面・印刷の描画
style.css / print.css
data/parts.json   … パーツの形・入数・値段
tools/check.mjs   … Node で番号を渡すと、パーツ割りの検算結果を出す（検証用）
```

## 4. 手順

### 手順1：Nouns のドットを取る（Mac で検証済みの方法）

1. seed をサブグラフから取る（CORS は許可されている）：
   - `POST https://api.goldsky.com/api/public/project_clnbcoajmebxn33wdbt98f439/subgraphs/nouns-mainnet/1.0.0/gn`
   - `{ "query": "{ noun(id: \"11\") { seed { background body accessory head glasses } } }" }`
2. パーツの絵は `https://unpkg.com/@nouns/assets@0.10.0/dist/image-data.json`（CORS 可）。
   中身は `palette`（色の配列、0 番は透明）と `images.bodies / accessories / heads / glasses[i].data`
3. `data` は RLE（ランレングス）。16 進文字列 `0x...` をバイト列にして：
   - `b[0]` はパレット番号（使わない）、`b[1]`=top、`b[2]`=right、`b[3]`=bottom、`b[4]`=left
   - `b[5]` 以降は（長さ, 色番号）の組。x=left, y=top から始め、長さぶん右へ塗る。色番号 0 は透明（塗らない）。**x が right に達したら x=left に戻して y+1**
4. **body → accessory → head → glasses の順に重ねる**（後のものが上）
5. 確認済み：Noun 11 で、この方法の 32×32 と noun.pics の画像（`https://noun.pics/11.png`、320×320＝1 ドット 10px）が 1,024 ドット全部一致した

### 手順2：色をブロックの色に寄せる

- Nouns のパーツは 238 色あるが、ブロックは約 18 色。各ドットを**いちばん近いブロックの色**にする（Lab 色空間の距離で選ぶ。RGB の距離だと肌色やグレーがずれやすい）

- 画面に「元の色 → ブロックの色」の対応表を出し、**対応を手で変えられる**ようにする（例：この水色はパステルブルーではなくダークブルーにしたい）

### 手順3：パーツ割り

- 入力：40×40 のマス目（各マスは「ブロックの色」か「空き」）。出力：パーツの一覧（形・向き・位置・色）
- ルール：
  - 同じ色のマスだけを 1 つのパーツにまとめる。空きマスには置かない。**全マスがちょうど 1 回ずつ覆われる**こと
  - 使える形は 2 の表のとおり（縦横どちらの向きも可）
  - **パーツの個数をなるべく少なく**する（大きい形から優先して置く貪欲法でよい。プロトでは最適でなくてよい）
  - **プレートの継ぎ目（x=20 の縦線、y=20 の横線）をまたぐ置き方を優先**する。4 枚のプレートは、上に載ったパーツでしかつながらないため
  - 同じ入力からは毎回同じ結果になること（乱数を使わない）
- 継ぎ目のチェック：4 つの継ぎ目（左上-右上、左下-右下、左上-左下、右上-右下）それぞれについて、またいでいるパーツの数と、**またぐパーツがない区間**（とくに背景だけの外側の端）を出す。
  またぐパーツが 0 の継ぎ目があれば、画面と組立図に「⚠ ここは割れやすい。裏打ちが必要」と出す（裏打ちパーツの自動追加はプロトではやらない）

### 手順4：組立図をつくる

画面にも印刷にも、次の 4 つを出す。

1. **完成図**：40×40 をポッチ付きのマス目で描く。プレートの境目に薄い線
2. **部品リスト**：形 × 色 × 個数。色の見本つき
3. **買い物リスト**：部品ごとに必要な袋数（`ceil(個数 ÷ 入数)`）と金額、20×20 プレート 4 枚、合計金額。入数と値段は `data/parts.json`：
   - 1袋 220円（税込）。入数：1×1=80、1×2=70、1×3=50、1×4=40、1×6=30、2×2=60、2×3=50、2×4=40、2×8=20
   - 20×20 プレート：1枚 220円（色は未確認。設定で選べるように）
   - 買う先は公式の Kawada Base（https://kawadabase.com/shop/product_categories/single-parts ）へのリンク
4. **組立手順**：プレート 1 枚ずつ（左上→右上→左下→右下）、その中を色ごとに 1 ステップにする。
   各ステップの図は、**置き済みのパーツを薄く、このステップで置くパーツを濃く＋枠線**で描き、「このステップで使う部品（形×個数）」を添える。
   継ぎ目をまたぐパーツは、2 枚目以降のプレートを並べたあとのステップで置く

- 画面では「◀ 前へ／次へ ▶」でステップを送れるようにする（スマホで見ながら組めるように）
- 「PDF で保存」ボタンは `window.print()`。`print.css` で A4 縦、1 ステップ＝1 ページ程度、ボタン類は印刷しない
- 表紙：Noun の番号、完成図、大きさ（1 ポッチ約 4mm なので約 16cm 角。実物で要確認）、パーツ総数、合計金額

### 手順5：表記

- アプリ名・表記は **ナオブロック（naoblock）**。「ナノブロック」はカワダさんの登録商標なので、アプリ名には使わない。部品の説明で使うときは注意書きを付ける
- フッターに：「Nouns は CC0 です」「nanoblock（ナノブロック）は株式会社カワダの登録商標です。本アプリは非公式のファン作品です」

## 5. 進め方

- `main` から作業ブランチを切り、PR を出す。マージはなおなお
- 1 回目の PR は「手順1〜3 と、完成図＋部品リスト」までで止めてよい。組立手順・印刷は 2 回目でもよい
- PR の説明に、`?noun=11` で開ける確認用 URL（GitHub Pages か raw.githack）と、`node tools/check.mjs 11` の出力を貼る

## 6. 検証チェックリスト（MacBook のちーちゃんがやる）

- [ ] Noun 0・11・1000 などで、復元した 32×32 が noun.pics の画像と全ドット一致する
- [ ] パーツ割りの検算：全マスがちょうど 1 回ずつ覆われている／空きマスに置いていない／1 つのパーツの中が同じ色／形は許可した 9 種だけ
- [ ] 部品リストの個数の合計＝パーツの個数、覆ったマス数の合計＝色の付いたマス数
- [ ] 袋数と金額の計算が合っている
- [ ] 継ぎ目の警告が、またぐパーツのない継ぎ目でだけ出る
- [ ] 同じ番号で 2 回作って、結果が同じ
- [ ] スマホの縦・横と PC で表示が崩れない。ステップ送りが動く
- [ ] Chrome で PDF に印刷して、A4 に収まり、ボタンが写っていない
- [ ] コンソールのエラーが 0

## 7. まだ分かっていないこと（なおなおが実物・ストアで確認）

- 1 ポッチの大きさ（約 4mm の想定）
