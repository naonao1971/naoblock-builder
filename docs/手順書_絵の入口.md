なおなおと 2026-10-14 に決めた内容です。決定事項は勝手に変えず、迷ったらなおなおに聞いてください。「（仮）」と書いたものは、なおなおに確認してから決めます。

※ 遊び方・ブロック・完成画面の決まりは `docs/手順書_ゲーム版.md` のまま。この手順書は**中の作りを整理するだけ**で、遊び方は変えません。

## 1. なぜやるか

このアプリは「組立図 → ゲーム → お試しの絵（これからはドット絵と呼ぶ）」と、作った順に機能が積み重なっている。これから絵の種類（チビ咲耶、手持ちの画像、月蝕綺譚 など）が増えるので、中を 3 つに分ける。

| 層 | 役割 | 主なファイル |
|---|---|---|
| ① 入口 | 絵を 40×40 の色のマス目にする | `src/nouns.js`・`src/picture.js` → **新しく `src/subjects.js` でまとめる** |
| ② 設計図 | マス目を部品と組む順番にする | `src/plan.js`・`tiling.js`・`steps.js`・`pieces.js`・`stages.js`（**変えない**） |
| ③ 遊び方 | 設計図で遊ぶ・印刷する・シェアする | `src/main.js`・`game.js`・`gameview.js`・`finish.js`・`print.js`・`ranking.js` |

いまは「絵が Nouns かどうか」を `main.js` の `trial` という目印 1 つで分けていて、お試しの絵は**ランキング・途中保存・シェアが使えない**。この PR で、③ が「絵の種類」を気にせずに動くようにする。

## 2. 決定事項（変えない）

| 項目 | 決定 |
|---|---|
| 目的 | **整理だけ**。遊び方・画面の見た目・部品割り（②）は変えない |
| 入口の形 | 絵 1 つを「**題材（subject）**」として表す。③ は題材が持っている情報だけを使い、Nouns かどうかで分岐しない |
| お試しの絵 | Nouns と同じく、**ランキング・途中保存・シェアが使える**ようにする。呼び方も「お試し」から「**ドット絵**」に変える |
| Nouns の保存 | **今までの途中保存・ランキングはそのまま読める**こと（保存の名前 `naoblock:game:v1:noun:<番号>:…` と `naoblock:ranking:v1:noun:<番号>:…` は変えない） |
| Nouns の URL | `?noun=12` はそのまま |
| 3D | **やらない**（後回し。なおなお 2026-10-14）。将来は「平面を段で積む」形で今のパズルを 1 段ずつ使う予定なので、② は 2D のままでよい |

## 3. 題材（subject）の形

`src/subjects.js` に置く。`main.js` の `start({ id, label, load })` が今すでに近い形なので、それを広げる。

```js
// 題材 1 つ分
{
  kind: 'noun',            // 'noun' | 'picture'（保存・ランキングの名前に入る）
  id: '12',                // kind の中での名前（Nouns は番号、絵はファイルの名前）
  label: 'Noun 12',        // 画面に出す名前
  load: async () => ({ grid, bgHex }),  // 40×40 の色（色コード or null）と背景色
  originalNote: '元絵：Nouns の本来の色と背景色',  // 「元絵」タブの説明
  shareText: (r) => '…',   // X のシェア文面（r = { pieces, elapsedMs, mode, guide }）
  url: (href) => '…',      // この題材を開く URL
  fileName: 'naoblock-noun12.png',  // 完成画像を保存するときの名前
}
```

- `subjectFromUrl(location.search)`：URL から題材を作る。当てはまらなければ `null`（スタート画面を出す）
- `nounSubject(n)`：今の `loadNoun` の中身を入れる。シェア文面・URL は今の `shareText`・`appUrl` と同じ結果になること
- `pictureSubject(name)`：今の `loadSample` の中身を入れる。絵の一覧（今の `SAMPLE_PICTURES`）もここに移す
- 保存・ランキングの名前は `kind` と `id` から作る：`naoblock:game:v1:${kind}:${id}:${mode}`。Nouns は `kind: 'noun'` なので**今と同じ名前になる**
- 純粋関数にできるところ（URL → 題材、シェア文面、保存の名前）は純粋関数にして、`tools/check.mjs` で確かめられるようにする

## 4. 直すところ

### 4-1. `trial` をなくす

`main.js` の `trial` を使っている所（2026-10-14 時点で宣言を除いて 12 か所）を、題材の情報に置き換える。

| 今 | これから |
|---|---|
| `loadSave`・`writeSave` の `if (trial) return` | なし（全部の題材で保存する） |
| `saveKey(id, mode)` | `saveKey(subject, mode)` |
| `$('mode-best').hidden = trial` | 常に出す |
| `drawSample` の元絵の説明 | `subject.originalNote` |
| 完成画面のランキング `ta && !trial` | `ta` だけ |
| 画像の保存名 | `subject.fileName` |
| シェアボタン `hidden = trial` | 常に出す。文面は `subject.shareText`、URL は `subject.url` |
| 印刷の URL | `subject.url(location.href)` |
| `recordRanking` の `ta && !trial` | `ta` だけ |

### 4-2. ランキング

- `src/ranking.js` の名前を `(kind, id, guide)` で作れるようにする。Nouns の名前は今と同じ
- 古いベスト記録（PR #9）の引き継ぎは Nouns だけでよい

### 4-3. ドット絵の URL・シェア

- `?sample=1` はそのまま開けるようにする（PR #16 の確認用 URL が残っているので）
- 新しい書き方 `?pic=<名前>` も受け付ける（なおなお OK 2026-10-14）。名前は `data/samples/` のファイル名（拡張子なし）
- シェアの文面：「<絵の名前> をナオブロックで組み立てた！ パーツ ○個・○分○秒 #naoblock」。ハッシュタグは **#naoblock だけ**（#Nouns も #咲耶 も付けない。なおなお OK 2026-10-14）
- タイムアタックの文面も Nouns と同じ形で、頭の「Noun ○」を絵の名前に、ハッシュタグを #naoblock だけにする

### 4-4. 呼び方を「お試し」から「ドット絵」に

ランキングも保存もシェアもできるようになるので、もう「お試し」ではない。画面の言葉を次のように変える（なおなおから「上手く変えて」と任された。2026-10-14）。

| 場所 | 今 | これから |
|---|---|---|
| スタート画面のリンク | お試し：ドット絵の画像で遊ぶ（ランキング・途中保存・シェアはありません） | **ドット絵で遊ぶ** |
| 絵の名前（`label`） | お試しの絵 1 | **ドット絵 1**（チビ咲耶を正式に入れるときに「チビ咲耶」にする） |
| 「元絵」タブの説明 | 元絵：お試しの絵の色（40×40 に縮めたもの） | **元絵：ドット絵の色（40×40 に縮めたもの）** |

- コードの中の名前も合わせる：`SAMPLE_PICTURES` → `PICTURES`、`kind: 'picture'`。`data/samples/` のフォルダ名は URL `?sample=` と合わせて今は変えない
- 文字以外の見た目（配置・色・大きさ）は変えない

## 5. 進め方

- PR は 1 本（「絵の入口を分ける」）。版の番号はいつもどおり上げる
- **見た目と遊び方が 1 つも変わらない**ことが一番大事。Nouns で遊んだ途中保存が消えたら失敗
- PR の説明に次を貼る：
  - 確認用 URL（コミット指定の raw.githack）：`?noun=11`、`?sample=1`、`?pic=1`
  - `node tools/check.mjs 11` の出力（変わっていないこと）
  - 足した検算（URL → 題材、保存の名前）の出力
