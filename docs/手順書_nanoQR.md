## 1. 作るもの

PR は 1 本。スタート画面の **nanoQR タブの「準備中」を外して**、URL を入れると QR コードを元絵にして遊べるようにする。

- 元絵は「**QR ＋ 白い余白 ＋ 黒い外枠**」の 1 枚
- そこから先（パズル・タイムアタック・組立図・PDF・買い物リスト・シェア）は、Nouns やドット絵と同じ仕組みをそのまま使う
- タイトルのブロック文字、立体のメガネは**この PR ではやらない**（次の PR）

## 3. 実装

### 3-1. URL → QR のマス目

- QR を作る部分は、小さなライブラリを `src/vendor/` に置く（例：qrcode-generator、MIT。ライセンスの一文をファイルの先頭に残す）。ビルドの仕組みは入れない。ES モジュールとして import できる形にする
- 誤り訂正は **M**、文字は UTF-8 のバイトモード
- バージョン（大きさ）は、入る中で**いちばん小さいもの**を自動で選ぶ。上限はバージョン 4（33×33）
- 戻り値：`modules`（N×N の true＝濃い / false＝明るい）と、目印の四角の場所

### 3-2. 元絵（40×40 以下の色）を作る

外側から：黒い外枠 1 マス → 白い余白 q マス → QR（N×N）→ 白い余白 q マス → 黒い外枠 1 マス

- 余白 q ＝ `min(4, floor((40 - 2 - N) / 2))`。どのバージョンでも 2 以上になる

| バージョン | N | q | 元絵の一辺 |
|---|---|---|---|
| 1 | 21 | 4 | 31 |
| 2 | 25 | 4 | 35 |
| 3 | 29 | 4 | 39 |
| 4 | 33 | 2 | 39 |

- 色は**パレットの色コードをそのまま**入れる（近い色に寄せる処理でずれないように）：ダークブルー `1a3a8a`、ホワイト `f4f4f4`、イエロー `fdd835`、ブラック `1a1a1a`
- 目印の四角（左上・右上・左下の 7×7）は、外側 1 マスの輪＝濃い色、その内側 1 マスの輪＝**イエロー**、真ん中 3×3＝濃い色
- 40×40 の真ん中に置くのは今の `buildBoard` がやる（一辺 39 なら 1 マス余る。余ったところはプレートの色＝ブロックなし）

### 3-3. 題材（`src/subjects.js`）

`qrSubject(url, colors)` を足す。

| 項目 | 中身 |
|---|---|
| kind | `'qr'` |
| id | 入れた URL（そのまま） |
| label | `nanoQR` |
| scope | `この QR` |
| URL | `?qr=<URL>`（`pageUrl(href, 'qr', url)`）。色を変えたときは `&dark=<色 id>&accent=<色 id>` も付ける（初期の色のときは付けない） |
| 保存・ランキング | 今の形のまま `naoblock:game:v1:qr:<URL>:<モード>`。**色は名前に入れない**（同じ URL なら同じ記録） |
| シェアの文面 | `shareTextFor('nanoQR', '#naoblock', …)` の後ろに、改行して `このQRの行き先：<URL>` を足す（**入れた URL を文面に出す**、なおなお決定 10/16） |
| fileName / pdfName | `naoblock-qr.png` / `nanoQR_naoblock.pdf` |
| originalNote | `元絵：QR コード（外枠と余白つき）` |

- `subjectFromUrl` に `?qr=` を足す。URL として正しくない・長すぎるときは null を返し、スタート画面の nanoQR タブを開いてメッセージを出す
- 入れられるのは `http://` か `https://` で始まる URL だけ（なおなお決定 10/16）
- 入れた URL を画面に出すときは `textContent` で（HTML として扱わない）

### 3-4. スタート画面の nanoQR タブ

- `CATEGORIES` の qr を `ready: true` にする
- 中身：
  - 説明の一文：「**あなたのサイトへの入口を、ナノブロックで作ろう**」（なおなお決定 10/16）。`CATEGORIES` の qr の `note` もこの文にする
  - URL の入力欄と「組み立てる」ボタン（押すと `?qr=…` へ）
  - 入れながら、**あと何文字入るか**を出す。入らないときは「長すぎます。あと◯文字短くしてください（短縮 URL も使えます）」と出してボタンを押せなくする
  - 色を選ぶ欄 2 つ（初期はダークブルー・イエロー）
    - 濃いマス：ブラック・ダークグレー・ダークブルー・グリーン・パープル・ブラウン・レッド（なおなお決定 10/16）
    - 目印の輪：イエロー・イエロー・オレンジ・パステルブルー・ピーチ・ベージュ・ライトグレー・ホワイト（なおなお決定 10/16）
    - 濃い色と明るい色が入れ替わると読めなくなるので、上の 2 つの組から外れる色は選べないようにする
  - 小さな見本（今の入力で出る元絵）を入力欄の下に出す

### 3-5. 版の番号

`src/version.js` と `index.html` の `data-version` を、この PR の番号にする。

## 4. 検算（`tools/check.mjs`）

`node tools/check.mjs --qr` を足す。ネットなしで動くこと。

- 長さの違う URL 4 本（バージョン 1〜4 になるもの）と、長すぎる URL 1 本で：
  - バージョン・一辺・余白が 3-2 の表どおり
  - 外枠がすべてブラック、余白がすべてホワイト、null のマスがない
  - 目印の輪が 3 か所ともイエロー、ほかにイエローがない
  - パーツ割りの検算（今の verifyTiling・verifyBlocks・verifySteps）が通る
  - 長すぎる URL はエラーになる
- `--subjects` に `?qr=` の題材（保存・ランキングの名前、シェアの文面、URL）を足す

## 5. 検証チェックリスト（MacBook のちーちゃん）

1. `node tools/check.mjs --qr` と `--subjects` がすべて OK
2. スタート画面の nanoQR タブが「準備中」ではなく、入力欄・色の欄・見本が出る
3. `https://naoblock.jp` を入れて組み立てる → 元絵が写真と同じ配色（青・白・黄の輪・黒い枠）
4. **元絵と完成画面の絵を jsQR で読んで、入れた URL に戻る**（バージョン 1〜4 の 4 本）。ヘッドレスの Chrome で（`~/dev/browser-automation/`）
5. 長すぎる URL で「あと◯文字」が出て、ボタンが押せない
6. 色を変えると URL に `&dark=` `&accent=` が付き、開き直しても同じ色。保存・ランキングは色を変えても同じ記録
7. れんしゅう・タイムアタックとも最後まで遊べる（バージョン 4 は白も埋めるのでパーツが多い。かかった時間をメモ）
8. 組立図 PDF・買い物リストが出る。パーツ数と金額をメモ（なおなおに伝える）
9. `?noun=11`・`?pic=chibi-sakuya` が今までどおり（保存・ランキングの名前が変わらない）
10. スマホ縦で、nanoQR タブの入力欄がはみ出さない
11. コンソールにエラーなし

**なおなおの確認**：印刷した組立図、または完成画面をスマホのカメラで読んで、URL に飛べること。
