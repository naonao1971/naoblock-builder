# naoblock builder 手順書（体験版：Nouns × 40×40 平面を画面で組み立てる）

スマホのちーちゃん（実装）へ。MacBook のちーちゃん（検証）が下の「検証チェックリスト」で確かめるので、その前提で作ってください。
なおなおと 2026-10-12 に壁打ちして決めた内容です。決定事項は勝手に変えず、迷ったらなおなおに聞いてください。

※ `docs/手順書_プロト.md`（紙・PDF の組立図を作るアプリ）は旧版です。方向が変わったので**こちらが正**です。ドットの取り方・色合わせ・パーツ割りは旧版と同じ内容をここに書き直してあります。

## 1. 作るもの

Nouns の番号を入れると、**ナノブロックの基本パーツで組める 40×40 の平面ドット絵を、組立説明書どおりに画面の上で 1 個ずつ組み立てて遊べる** Web アプリ。
主役は「組み立てる体験」。紙の組立図は作らない（部品リスト・買い物リストは完成画面からのおまけとして出す）。

最終的には「キャラを選ぶ（MCP）→ チビ化 → 立体のミニナノ」まで広げるが、**プロトは平面・Nouns だけ**。

## 2. 決定事項（変えない）

### 体験（2026-10-12 決定）

| 項目 | 決定 |
|---|---|
| 組み方 | **ガイド付き**。「次はこのパーツ」と 1 個ずつ出て、置く場所が光る |
| 1 回の量 | 1 個ずつ置ける。加えて **「このステップの残りを自動で置く」ボタン**。自動でも 1 個ずつ「カチカチッ」と置かれていく様子を見せる |
| 見え方 | **真上から見た平面**。ポッチ付きのマス目 |
| 操作 | **タップだけ**。光っている場所をタップ → パーツが上から「カチッ」とはまる。違う場所をタップ → 軽く揺れて、光っている場所を教える。ドラッグはしない |
| ズーム | 拡大・縮小できる（ピンチ＋ボタン）。次のパーツが画面の外なら、そこへ自動でスクロール |
| 途中保存 | **途中まで組んだ状態を自動で保存**（ブラウザの localStorage、Noun の番号ごと）。同じ Noun を開いたら「続きから／最初から」を選べる。かかった時間も続きから数える |
| 完成画面 | 完成図を大きく＋「Noun 11 完成！ 使ったパーツ ○個・かかった時間 ○分」。**画像を保存**ボタン、**X にシェア**ボタン、その下に「実物で組むなら」として部品リスト・買い物リスト（金額つき） |

あとから足す候補（プロトではやらない）：完成したら立体でくるっと回す演出、ガイドなしで組む「自由モード」、20×20 だけの短いモード。

### 作品（前の版から引き継ぎ）

| 項目 | 決定 |
|---|---|
| 形 | 平面。プレートの上に 1 段だけブロックを並べる |
| 土台 | 20×20 プレートを 2×2 で 4 枚＝ 40×40 |
| 配置 | Nouns の 32×32 を、40×40 の真ん中（上下左右に 4 ポッチの余白）に 1 ドット＝1 ポッチで置く。縮めない |
| 背景 | **ブロックを置かない**（プレートの色のまま）。Nouns の背景色は使わない |
| パーツ | パラ売りの長方形の基本パーツだけ：1×1・1×2・1×3・1×4・1×6・2×2・2×3・2×4・2×8（回転可） |
| 色 | 単色部品で買える色だけ（下の表）。クリア系は使わない |
| 置き場所 | リポジトリ naonao1971/naoblock-builder。GitHub Pages で公開。完成後に naoblock.jp からリンク |

## 3. 技術の方針

- ビルドなしの静的サイト。`index.html` ＋ ES Modules（素の JS）。ライブラリは使わない
- 描画は `<canvas>`（マスが 1,600 あるので DOM より軽い）
- **中身の計算（Nouns の取得以外）は純粋な関数**にして、ブラウザでも Node でも `import` できるようにする（検証で Node から呼ぶため）
- URL の `?noun=11` で番号を指定できるようにする
- 音は Web Audio で鳴らす（音声ファイルは置かない）。消音ボタンを付ける

ファイル構成の目安：

```
index.html
src/nouns.js      … seed の取得と 32×32 への復元
src/palette.js    … ブロックの色の表と、いちばん近い色を選ぶ処理
src/tiling.js     … パーツ割り（純粋関数）
src/steps.js      … 組立順（ステップとパーツの並び）を作る（純粋関数）
src/plan.js       … 部品リスト・買い物リスト（純粋関数）
src/board.js      … 盤面の描画・ズーム・タップ判定
src/play.js       … 遊びの進行（次のパーツ、正誤、自動で置く、時間計測、途中保存）
src/finish.js     … 完成画面（画像保存・シェア・リスト）
src/kit.js        … 2D・3D 共通の部品（音・紙吹雪・コンボ・♥・PDF）の読み込み。中身は naoblock-kit
style.css
data/parts.json   … パーツの形・入数・値段
tools/check.mjs   … Node で番号を渡すと、パーツ割りと組立順の検算結果を出す（検証用）
```

## 4. 手順

### 手順1：Nouns のドットを取る（Mac で検証済みの方法）

1. seed をサブグラフから取る（CORS は許可されている）：
   - `POST https://api.goldsky.com/api/public/project_clnbcoajmebxn33wdbt98f439/subgraphs/nouns-mainnet/1.0.0/gn`
   - `{ "query": "{ noun(id: \"11\") { seed { background body accessory head glasses } } }" }`
2. パーツの絵は `https://unpkg.com/@nouns/assets@0.10.0/dist/image-data.json`（CORS 可）。
   中身は `palette`（色の配列、0 番は透明）と `images.bodies / accessories / heads / glasses[i].data`
3. `data` は RLE。16 進文字列 `0x...` をバイト列にして：
   - `b[0]` はパレット番号（使わない）、`b[1]`=top、`b[2]`=right、`b[3]`=bottom、`b[4]`=left
   - `b[5]` 以降は（長さ, 色番号）の組。x=left, y=top から始め、長さぶん右へ塗る。色番号 0 は透明。**x が right に達したら x=left に戻して y+1**
4. **body → accessory → head → glasses の順に重ねる**（後のものが上）
5. 確認済み：Noun 11 で、この方法の 32×32 と `https://noun.pics/11.png`（320×320＝1 ドット 10px）が 1,024 ドット全部一致した

### 手順3：パーツ割り

- 入力：40×40 のマス目（各マスは「ブロックの色」か「空き」）。出力：パーツの一覧（形・向き・位置・色）
- ルール：
  - 同じ色のマスだけを 1 つのパーツにまとめる。空きマスには置かない。**全マスがちょうど 1 回ずつ覆われる**こと
  - 使える形は 2 の表の 9 種（縦横どちらも可）
  - **パーツの個数をなるべく少なく**（大きい形から置く貪欲法でよい）
  - **プレートの継ぎ目（x=20 の縦線、y=20 の横線）をまたぐ置き方を優先**する
  - 同じ入力からは毎回同じ結果（乱数を使わない）
- 継ぎ目をまたぐパーツが 0 の継ぎ目があれば、完成画面の「実物で組むなら」に「⚠ ここは割れやすい。裏打ちが必要」と出す（画面で遊ぶぶんには関係ない）

### 手順4：組立順（ステップ）を作る

- プレート 1 枚ずつ（左上→右上→左下→右下）、その中を色ごとに 1 ステップにする
- 継ぎ目をまたぐパーツは、またぐ両方のプレートのステップが終わったあとの「つなぎ」ステップで置く
- ステップ内のパーツの順番は、**上の行から、同じ行なら左から**（パーツの左上のマスで並べる）。迷わず目で追えるように
- 出力：ステップの配列。各ステップに「プレート・色・パーツの並び」

### 手順5：遊ぶ画面

画面の構成（スマホ縦を基準に）：

- 上：「ステップ 3 / 14　左上プレート・ブラック」と、全体の進み具合のバー
- 真ん中：盤面（真上から見たポッチ付きのマス目、プレートの境目に薄い線）
  - 置いたパーツ：ブロックの色で、パーツの輪郭が分かるように描く
  - **次に置くパーツの場所：光る（点滅する枠＋薄い色）**
  - このステップでこの後置く場所：さらに薄く見せる（先の見通し用）
- 下：「次のパーツ」の見本（形と色、例「1×4 ブラック」）と、このステップの残り個数。ボタンは「残りを自動で置く」「ズーム」「消音」

動き：

1. 光っている場所（パーツが覆うマスのどれか）をタップ → パーツが上から落ちて「カチッ」と鳴ってはまる → 次のパーツが光る
2. 違う場所をタップ → 光っている枠が軽く揺れる（音は控えめ）。間違いは数えない
3. 「残りを自動で置く」→ このステップの残りを 1 個ずつ短い間隔（目安 0.1〜0.15 秒）で「カチカチッ」と置いていく。途中でタップしたら止まる
4. ステップが終わったら「ステップ 3 完了！」を短く出して、次のステップへ
5. 次のパーツが画面の外なら、そこへ自動でスクロール
6. タップの当たり判定は、拡大していなくても指で押せるよう、光っているパーツの周り 1 マスまで広げてよい
7. 置くたびに進み具合を localStorage に保存する。開き直したら「続きから／最初から」を選べる

お手本の絵（盤面の隅に完成図）：

- 遊ぶ画面の右上に、**完成図の小窓**を常に出す
  - 中身は、ブロックの色に置き換えたあとの 40×40 の完成形。背景はプレートの色
  - 大きさはスマホ縦で 80〜100px 角くらい。盤面の操作のじゃまにならない位置に置く
  - ズームやスクロールをしても、小窓は動かない（画面に固定）
  - **今置いているステップの範囲**（プレート 1 枚ぶん、またはつなぎのパーツ）を、小窓の上で細い枠で示す。全体のどこを組んでいるかが分かるように
- 小窓をタップすると**大きく表示**する（盤面の上に重ねる。閉じるボタンか、外側のタップで閉じる）
  - 大きく表示した画面に「完成図／元絵」の切り替えを付ける
  - **元絵**は、Nouns の 32×32 をブロックの色に寄せる前の本来の色で描く（`nouns.js` で復元した 32×32 と元のパレットをそのまま使い、Nouns の背景色も付ける。noun.pics は読まない）
  - 完成図と元絵は同じ大きさ・同じ位置で切り替えて、見比べられるようにする
- 絵はどちらもドットがくっきり見えるように描く（ぼかさない）

遊び方の案内（最初の 1 回だけ）：

- 初めて開いたときだけ、盤面の上に短い案内を出す
  - 「光っているところをタップすると、ブロックがはまります」
  - 「右上の小さな絵が完成図です。タップすると大きく見られます」
  - 「面倒になったら『残りを自動で置く』でどんどん進められます」
- 「はじめる」ボタンで閉じる。閉じたことは localStorage に保存して、2 回目からは出さない
- 画面のどこか（消音ボタンの近くなど）に「？」ボタンを置いて、いつでも案内を出し直せるようにする

### 手順6：完成画面

- 完成図を大きく表示（ステップの光や薄い表示は消した、きれいな絵）
- 「Noun 11 完成！」「使ったパーツ ○個」「かかった時間 ○分○秒」（最初のタップから最後のパーツまで。途中保存をはさんでも続きから数える）
- **画像を保存**：canvas を PNG にしてダウンロード（ファイル名 `naoblock-noun11.png`）。完成図の下に「naoblock」の小さな文字を入れる
- **X にシェア**：`https://x.com/intent/post?text=...&url=...` を開く。文面例「Noun 11 をナオブロックで組み立てた！ パーツ 512個・12分 #naoblock #Nouns」＋アプリの URL（`?noun=11` 付き）
  - intent では画像を自動で付けられないので、「画像を保存してから貼ってね」と一言添える
- **実物で組むなら**（折りたたみでよい）：
  - 部品リスト：形 × 色 × 個数、色の見本つき
  - 買い物リスト：部品ごとの袋数（`ceil(個数 ÷ 入数)`）と金額、20×20 プレート 4 枚、合計金額。`data/parts.json`：
    - 1袋 220円（税込）。入数：1×1=80、1×2=70、1×3=50、1×4=40、1×6=30、2×2=60、2×3=50、2×4=40、2×8=20
    - 20×20 プレート：1枚 220円
    - 買う先は公式の Kawada Base（https://kawadabase.com/shop/product_categories/single-parts ）へのリンク
  - 継ぎ目の警告（手順3）
- 「もう一度」「別の Noun で遊ぶ」ボタン

### 手順7：表記

- アプリ名・表記は **ナオブロック（naoblock）**。「ナノブロック」はカワダさんの登録商標なので、アプリ名には使わない
- フッターに：「Nouns は CC0 です」「nanoblock（ナノブロック）は株式会社カワダの登録商標です。本アプリは非公式のファン作品です」

### 手順8：部品リストと印刷（紙の組立図）

画面で遊んだあと、**実物を組むための紙**を出せるようにする。手順6の完成画面の「実物で組むなら」に「**組立図を印刷**」ボタンを置き、`window.print()` で印刷（PDF 保存もこれで）する。遊ぶ画面とは別の、印刷用の並べ方にする。

印刷する中身（この順）：

1. **表紙**：「Noun 11」、完成図（ポッチ付きのマス目、プレートの境目に薄い線）、大きさの目安（1 ポッチ約 4mm で約 16cm 角。実物で要確認）、パーツの総数、合計金額、アプリの URL（`?noun=11` 付き）
2. **部品リスト**：形 × 色 × 個数、色の見本つき。チェック欄（□）を付けて、袋から出した部品を数えながら印を付けられるようにする
3. **買い物リスト**：手順6と同じ中身（袋数・金額・プレート 4 枚・合計、Kawada Base の URL を文字で）。継ぎ目の警告もここに
4. **組立手順**：手順4のステップを順に。各ステップの図は、**置き済みのパーツを薄く、このステップで置くパーツを濃く＋枠線**で描き、「ステップ 3 / 32　左上プレート・ライトグレー」と「このステップで使う部品（形 × 個数）」を添える
   - 1 ページに 4 ステップ（2×2）を目安に。ステップの途中でページが切れないようにする
   - 図はプレート 1 枚ぶんだけ拡大してもよい（つなぎのステップは全体図）

印刷のルール：

- `print.css` で A4 縦。ボタン・小窓・フッター以外の画面部品は印刷しない
- 図は canvas から画像にして差し込み、ドットがぼけないように描く
- 白黒で印刷しても読めるように、ステップ図の「このステップで置くパーツ」は濃い枠線で区別する
- 部品リスト・買い物リストの数字は、`src/plan.js` の結果をそのまま使う（画面と紙で数字がずれないように）
